As you navigate through folders, the layout adapts based on the type of content being displayed. **Folders** are labeled with their names. **Playlists, images, radio stations and videos** are additionally highlighted for easier recognition — each kind gets its own section with its own heading and count.

You can also filter the displayed content by entering text into the **Search in this page** box.

A listing keeps itself up to date: if the media server reports a change — a file added to the folder,
a cover that was just updated, a rating written from another browser — only the entries that actually
changed are replaced, so the page does not jump while you are reading it.

The header of every browse page carries the cover and title of the current container, the control buttons on the left
and the filters on the right. Scrolling down collapses it into a slim sticky bar that keeps both groups reachable.

### Filters

The right side of the header narrows down what the page shows. The filters apply to everything on the current page —
folders, playlists, albums and tracks — and they are combined: an item has to pass all of them to stay visible. The
section headings count what is left, and **PLAY** / **SHUFFLE** send exactly the tracks the filtered list shows, so a
filtered page plays as it reads. A filter that is in use is highlighted; clicking the <span class="material-symbols-outlined">close</span>
icon resets it. Only the filters that make sense for the current page are displayed.

## Server Side Playlists

### MY PLAYLISTS in the sidebar

The **MY PLAYLISTS** section of the sidebar lists the playlists you have **liked**, wherever they are
stored on the media server. There is no playlist folder to configure any more: nextCP/2 asks the
media server for every playlist rated as liked, so a playlist appears no matter which directory it
lives in.

To put a playlist there, open its [folder options](#folder-options) — the
<span class="material-symbols-outlined">more_horiz</span> button on its tile, or the three dots in
the header once you are inside it — and choose **Like playlist**. **Unlike playlist** takes it out of
the sidebar again; the playlist file itself is not touched.

This requires a media server that can search on the rating, which means UMS 16 or newer. Without one
the section stays empty.


### Create Server Side Playlist

To create a server-side playlist, first navigate to the folder where you want the playlist to reside. Next, click the three-dot menu located next to **MY PLAYLISTS**. A dialog box will appear where you can enter the name for your new playlist and confirm your choice.

### Add songs to Server Side Playlist

To add a song to a server side playlist, navigate to the desired song, click on the three dots to open the song options dialog, then select **Add to playlist** and select the desired playlist.

### Delete Server Side Playlist

Click the three-dot menu next to **MY PLAYLISTS** to open the options dialog. Switch to **delete playlist**, locate the playlist you want to remove (the search field narrows the list down) and click **delete**. Deleting a playlist on the media server cannot be undone, so it has to be confirmed once more.

## View templates

### Album View

<Image src={imgA1} alt="" />

When browsing a container that contains only tracks from the same album, the interface switches to a track-based display.  

Clicking on a track title will immediately play that track rather than adding it to the current playlist.  

If the album is identified by a **MusicBrainz Release ID**, the like/dislike feature (heart icon) becomes available. Albums you mark as liked can then be quickly accessed from the **My Albums** section in the sidebar.

Songs can be rated from **1 to 5 stars** by clicking on the desired star icon. If a MusicBrainz user account is configured in the **App Settings**, your ratings can be submitted directly to [MusicBrainz.org](https://www.musicbrainz.org).

### Multi Disc Support

<Image src={imgMD} alt="" />

To manage a multi-disc release, copy all audio files into a single folder. If the tracks are tagged with the correct **numberOfThisDisc** ID3 metadata, the songs will be automatically sorted first by disc number and then by track ID.


###  Playlist view

<Image src={imgPV} alt="" />

When browsing server-based playlists, the display automatically switches to a track view with small album covers. Clicking **Switch View** will change the display to a full-sized album view.

### Videos

Video items are listed in a **Videos** section of their own. Clicking one hands it to the selected
player: a UPnP renderer that can show video plays it, and with **This Device** selected it opens in a
full screen player inside the browser tab — see
[Video in the browser](/nextcp2/user_interface/player_bar/#video-in-the-browser).

Both actions will be executed on the server side, so the changes will be reflected in the playlist file itself. The playlist has to be a `m3u` or `m3u8` file.

Removing songs can only be done, if the current view displays a playlist file.

<Bullets title="Player playlist actions">
    <li>Play next</li>
    <li>Add to queue</li>
</Bullets>

When the current media player is in **playlist mode**, selecting **Play next** will add the song to the playback queue in the next position, while **Add to queue** will place the song at the end of the current renderer playlist. If the media player is **not in playlist mode**, the selected song will play immediately, regardless of which action is chosen.


<Bullets title="Other server actions">
    <li>Download</li>
    <li>Update album art</li>
</Bullets>

You can `download` a resource, or `Update album art` on the server side.

<Bullets title="Live title of this station">
    <li>Detect automatically</li>
    <li>Artist &ndash; Title</li>
    <li>Title &ndash; Station</li>
</Bullets>

Web radio entries carry one more group. Stations announce the running track as a single line of text
(ICY metadata), and they do not agree on what that line contains: most send `Artist - Title`, some
send `Track - Station`. **Detect automatically** lets the media server guess; if a station is
consistently shown the wrong way round, pin the order here. The setting belongs to the station and is
stored with it on the media server, so it applies to every renderer and every browser.

## UPnP Search

<video src="/nextcp2/anim/search.mp4" poster="/nextcp2/anim/search.poster.webp"
       autoplay loop muted playsinline controls preload="metadata"
       class="block w-full h-auto my-4 rounded-lg" aria-label="Searching the whole library from the global search box"></video>

If the selected media server supports UPnP search, entering text into the **Global Search** box will initiate a server-side search request.  

Known media servers with compatible UPnP search capabilities include [MinimServer](https://minimserver.com/) and [Universal Media Server (since 10.6.0)](https://www.universalmediaserver.com/). The search text is matched against tracks, albums, playlists, and artists. Artist covers are retrieved from Spotify if a connected account is available.

Clicking on a song item will play that song immediately. Clicking on any other item will navigate into that content.

The dropdown shows the first hits per kind. **show all (N)** next to a group turns the query into a
full result page — a page like any other browse page, with the same control buttons and filters, so
the hits can be played, shuffled, sorted or narrowed down further. The result page carries a bar with
every kind of hit the query has (*Albums*, *Tracks*, *Artists*, *Playlists*) and their counts, so
switching from albums to tracks is one click instead of searching again.
